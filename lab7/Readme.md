## Завдання 1. Filter

Критерії: `x > K`; `w.Length > 5`; `s.Score >= 75`.

Вивід (вставити після запуску):

```
числа > 1: ...
рядки довші за 5: ...
студенти з балом >= 75: ...
```

Очікувано для рядків: 10 слів (усі, крім «код», «дані», «цикл», «ікс»). Для студентів: 6
(Коваленко, Іщенко, Ткачук, Кравець, Мороз, Бойко).
Числа лежать у [−1; 1], а критерій «> K» означає «> 1», тому результат для чисел порожній
(розмір 0). Це не помилка алгоритму, а наслідок варіанта.

Скільки разів я змінював тіло `Filter` між трьома застосуваннями: **нуль**.

## Завдання 3. Aggregate

Усі чотири величини отримано одним `Aggregate<T, TAcc>`, нових циклів немає.

| Агрегація | Стан | Старт | Крок |
|---|---|---|---|
| сума | `int` | `0` | `(acc, x) => acc + x` |
| добуток | `int` | `1` | `(acc, x) => acc * x` |
| максимум | `int?` | `null` | `(acc, x) => acc == null \|\| x > acc ? x : acc` |
| конкатенація через кому (c = 2) | `(string text, bool any)` | `("", false)` | `(acc, w) => (acc.any ? acc.text + "," + w : w, true)` |

Для максимуму накопичувач `int?`, а старт `null`: на порожньому списку результат `null`
(виводиться «немає»), а не вигадане число на кшталт `int.MinValue`. Для суми й добутку
на порожньому списку повертається 0 та 1: це нейтральні елементи, і такий результат
математично коректний. Прапорець `any` у конкатенації потрібен, щоб не ставити кому перед
першим елементом (і щоб правильно працювати, навіть якщо перший рядок порожній).

## Завдання 5. Захоплення змінних

Вивід програми (вставити після запуску; нижче — що має вивестися):

```
1) поріг = 1: above(5) = True
   після threshold = 1000: above(5) = False
2) for: 3, 3, 3
3) foreach: 0, 1, 2
   виправлений for: 0, 1, 2
```

1. **Змінна після лямбди.** Лямбда захоплює саму змінну `threshold`, а не її значення на
   момент створення делегата. Значення читається в момент виклику, тому після присвоєння
   1000 той самий делегат уже порівнює з 1000.
2. **Лічильник `for`.** Змінна `i` оголошена один раз на весь цикл, тому всі три лямбди
   захоплюють одну й ту саму змінну. Коли цикл завершується, `i` дорівнює 3, і всі
   делегати повертають 3.
3. **`foreach`.** Змінна циклу `v` у кожній ітерації створюється заново (так працює
   `foreach` починаючи з C# 5), тому кожна лямбда захоплює власну змінну: 0, 1, 2.

Виправлення пункту 2: у тілі циклу зробити копію (`int copy = i;`) і захопити `copy`.

## Завдання 6. Висновок

**1. Скільки функцій без узагальнення і з ним.** Коли критерій зашитий у функцію, кожна
пара «критерій + тип даних» потребує окремої функції: три критерії для трьох типів — це
три окремі функції `FilterNumbers`, `FilterStrings`, `FilterStudents` (а якщо кожен
критерій застосовувати до кожного типу, то дев'ять). Тут достатньо одного `Filter<T>`:
три критерії передаються як три лямбди, а тіло алгоритму не змінюється. Новий критерій чи
новий тип даних не додає жодної функції в бібліотеку.

**2. Де узагальнення було б зайвим.** У Лабораторній 6 функція `AverageScore(List<Student>)`
рахує середній бал студентів і використовується в одному місці для одного типу. Якби я
зробив її узагальненою (`Average<T>(List<T>, Func<T, int> selector)`), код став би
складнішим для читання, а виграшу не було б: другого типу даних або другого поля, для
якого потрібне середнє, у задачі немає. Узагальнювати варто тоді, коли змінна частина
справді змінюється (різні типи, різні критерії), а не «про запас».
